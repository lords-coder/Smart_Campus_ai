# SmartCampus UI Design System

The global visual foundation: the tokens, the shell's class inventory, and the
rules for adding to both. The palette and the shell come from the visual
prototype at `C:\test\tt\frontend`; this document is what the rest of the
application codes against.

Individual dashboards, cards, tables and charts are **not** covered here — they
are the deferred Frontend 2.0 work.

---

## 1. Two layers, one palette

| Layer | File | Generated by | Scope |
|---|---|---|---|
| Prototype shell | `src/styles/app-shell.css` | `scripts/scope-command-center-css.mjs` | global (the prototype's own selectors) |
| Shell additions | `src/styles/app-shell-overrides.css` | hand-written | global |
| Prototype Command Center | `src/styles/command-center.css` | `scripts/scope-command-center-css.mjs` | `.command-center-surface` |
| Command Center additions | `src/styles/command-center-overrides.css` | hand-written | `.command-center-surface` |
| Dark theme | `src/styles/theme-dark.css` | `scripts/build-dark-theme.mjs` | `:root` |

Import order in `src/app/globals.css` matters: the dark theme must be imported
after Tailwind (it overrides Tailwind's `:root`), and each `*-overrides.css` must
be imported after the stylesheet it corrects.

**Never edit a generated file.** Edit the prototype and re-run the codemod, or
edit the script.

```bash
cd frontend
node scripts/scope-command-center-css.mjs   # shell + Command Center layers
node scripts/build-dark-theme.mjs           # dark theme
```

Both scripts self-verify and exit non-zero on a leak.

### 2.2 shadcn semantic tokens

Declared on `:root` in `theme-dark.css` and consumed by every component through
Tailwind utilities (`bg-card`, `text-muted-foreground`, `border-border`,
`bg-primary`, `hover:bg-accent`, `text-destructive`, …). This is how the fifteen
already-built phases follow the new palette without being touched.

| Token | Value | Maps to |
|---|---|---|
| `--background` | `#070f1b` | `--ink-950` |
| `--foreground` | `#f0f6fb` | `--text-primary` |
| `--card` / `--card-foreground` | `#101f32` / `#f0f6fb` | `--surface` |
| `--popover` / `--popover-foreground` | `#14273c` / `#f0f6fb` | `--surface-raised` |
| `--primary` / `--primary-foreground` | `#37d7d1` / `#05161c` | the brand aqua |
| `--secondary`, `--muted` | `#0e1b2a` | `--surface-soft` |
| `--secondary-foreground`, `--muted-foreground` | `#a4b6c8` | `--text-secondary` |
| `--accent` / `--accent-foreground` | `#16283c` / `#e8f1f8` | the *hover surface*, not the brand |
| `--destructive` | `#e5484d` | strong red, white text on top |
| `--border` | `rgba(158, 188, 214, 0.14)` | identical to the prototype's |
| `--input` | `rgba(158, 188, 214, 0.2)` | field borders |
| `--ring` | `rgba(77, 230, 221, 0.55)` | focus |
| `--chart-1..5` | aqua, blue, violet, amber, green | reserved; no charts ship yet |
| `--sidebar*` | mirrors the above | reserved; the shell uses the prototype CSS |

**The one name to remember:** shadcn's `--accent` is a *subtle hover surface*.
The brand colour is `--primary` (equivalently the prototype's `--sc-accent`).
Re-declaring `--accent` as the brand aqua on `.app-shell` was the reason the
prototype's accent scale had to be renamed.

### 2.3 Radii and shape

`--radius: 0.75rem` (12 px) drives Tailwind's `rounded-sm`…`rounded-4xl`, which
matches the prototype's card radii of 12–15 px. The prototype's own rules use
literal pixel radii (9–16 px) and are not affected. Pills and circles
(`rounded-full`) are unchanged.

### 2.4 Palette compatibility

About two hundred utilities in the phase components reference Tailwind's palette
directly (`bg-gray-100`, `text-red-800`, `border-green-300`). The rule applied by
`scripts/build-dark-theme.mjs`:

| Shade | Used as a surface | Used as text |
|---|---|---|
| 50–300 | dark tinted surface (19 % → 39 % lightness) | light tint (97 % → 85 %) |
| 400–900 | **left at Tailwind's default** (solid brand fill) | light tint (78 % → 94 %) |

Each family keeps its real hue and chroma, read from Tailwind's own default
theme, with a chroma floor for the neutral families so they read navy rather than
pure gray. Semantic meaning is preserved: `bg-red-100 text-red-800` is still the
same red pairing, on a dark surface.

**When adding UI, prefer the semantic tokens.** A raw `bg-<family>-<shade>` will
be re-mapped by the generator whether you like it or not.

## 3. Typography

One family for the whole product: **Geist**, loaded through `next/font/google` as
`--font-sans` on `<html>`. The prototype's stylesheet asked for Inter, which the
integration never loads, so shell and content share Geist rather than splitting
between a loaded and an unloaded family. `.command-center-surface` sets
`font-family: var(--font-sans)` for the same reason.

| Role | Size | Weight | Token |
|---|---|---|---|
| Page title (`.page-header__title`) | `clamp(22px, 2.4vw, 30px)` | 690, `-0.035em` | `--text-primary` |
| Page description | 12 px / 1.6 | 400 | `--text-muted` |
| Command Center hero | `clamp(25px, 3vw, 38px)` | 690, `-0.047em` | `--text-primary` |
| Nav label | 13 px | 400 (650 active) | `--text-secondary` |
| Group label | 9–10 px, `0.14em` | 700–740, uppercase | `--text-faint` |
| Topbar context | 13 px, `0.012em`, uppercase | 650 | `#e8f1f8` |
| Card value | 27 px+ | 700 | `--text-primary` |
| Caption / helper | 9–11 px | 400–500 | `--text-muted` |

> `text-transform: uppercase` changes what `innerText` reports, which the E2E
> suites match against. Never uppercase a string a test asserts on — the
> "Quick actions" heading is the case that already bit us.

### Spacing system

| Element | Padding |
|---|---|
| `.page-surface`, `.command-center-surface` | `31px clamp(22px, 3vw, 44px) 38px`, `23px 15px 30px` ≤680 px, `23px 12px 30px` ≤390 px |
| `.page-header` | `0 0 26px` (`20px` ≤680 px) |
| `.page-main` | none — the surface owns the padding |
| `.sidebar` | `25px 16px 18px` |
| `.topbar` | `0 clamp(22px, 3vw, 44px)`, `67px` min-height ≤900 px, `62px` ≤680 px |

Both the page container and the Command Center surface use **one** rule
(`.page-surface, .command-center-surface`) so a page and the dashboard share the
same rhythm.

### Transitions

Only the prototype's own durations and easing (`--ease-out`):

| Interaction | Duration |
|---|---|
| sidebar collapse, drawer open/close | 220 ms |
| nav link hover/active | 160 ms |
| icon button, profile menu | 150 ms |
| topbar search, account menu | 160 ms |
| command palette in | 140 ms fade + 170 ms rise |
| page entry | none — the prototype has no page transition, and none was invented |

`@media (prefers-reduced-motion: reduce)` collapses all of them to 0.01 ms for
`.app-shell` and `.auth-surface` and their descendants.

## 5. Surfaces outside the shell

`.auth-surface` (in `globals.css`) paints the same navy gradient for `/login`,
`/parent/activate`, the root redirector and the session-restoring states. It also
declares `--blue`, which the brand mark's rule needs outside the shell.

`/verify/[code]` is a public certificate page with its own dark slate palette and
is intentionally not part of the shell.

## 6. Rules

1. **Use semantic tokens, not raw palette shades**, in anything new:
   `bg-card`, `text-muted-foreground`, `bg-primary`, `text-destructive`.
2. **Never hard-code a surface colour.** If a surface is needed that the tokens
   do not cover, add a token.
3. **New shell classes go in `app-shell-overrides.css`**, never in the generated
   `app-shell.css`, so regenerating the prototype cannot discard them.
4. **New navigation goes in `nav-config.ts`**, with the roles its page's
   `RoleGuard` accepts. No entry for a route that does not exist.
5. **A control that cannot do the thing it advertises does not ship.** The
   prototype's "isn't connected" toast, its empty search field and its
   notifications bell were removed rather than styled.
6. **`aria-current` on navigation, `role`/`aria-*` on anything interactive**, and
   a visible focus ring on everything in the tab order.
7. **Test-visible strings stay lowercase.** `text-transform` breaks `innerText`
   assertions.
